# Domain docs

Layout: single-context.

Antes de explorar, leer `CONTEXT.md` y los ADR de `docs/adr/` relacionados con el trabajo.

Usar el vocabulario del glosario en propuestas, issues y pruebas.
Si falta un concepto, señalarlo para `domain-modeling`.

Si una propuesta contradice un ADR, identificar la decisión y explicar por qué se propone revisarla.

Si algún documento no existe, continuar sin crearlo anticipadamente.
`domain-modeling` crea términos y decisiones cuando se resuelven.

# Conservar asignaciones anteriores al reutilizar un alias

El usuario eligió conservar el historial para que pueda resultar útil ante requisitos desconocidos de las etapas 2 y 3. Reasignar un alias crea una nueva asignación con identidad propia y conserva los datos de las anteriores; la resolución del enlace público debe seleccionar solamente la asignación vigente.

Se prefirió conservar esta información frente a descartarla al reciclar el alias, porque los datos eliminados no podrían reconstruirse cuando aparezca una nueva necesidad. La consecuencia aceptada es que reciclar códigos públicos no impide el crecimiento del historial persistido. En Q18 se acordaron identificador de asignación, alias, destino completo, creación y vencimiento, sin purga automática durante el trabajo.

Este acuerdo conserva asignaciones; no implica recopilar visitas, habilitar una consola ni desarrollar estadísticas en la primera etapa. Si se agregan estadísticas posteriormente, no se podrán reconstruir visitas anteriores a su incorporación a partir de este historial.

Acuerdos: respuestas Q9 y Q18 de la entrevista iniciada el 2026-10-05.
